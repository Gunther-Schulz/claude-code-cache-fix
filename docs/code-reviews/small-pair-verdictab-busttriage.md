**Skip list is derived, not hardcoded** — the brief's requirement and the
reason: a name roster goes red the day a fixture is added, i.e. it fires on a
non-defect. The oracle walks the parsed fixture for a non-empty `messages`
array at *any* depth. That derivation shares no code and no shape assumptions
with the tool's three-shape (`requests` / `records` / `.jsonl`) reader, so it
is an independent check rather than a restatement — and it agrees with the tool
on the current corpus (6 read / 3 skipped). Both halves of the partition are
asserted: skipping is checked *and* every message-array fixture is asserted
present as a read corpus, since checking only the skip list would still let a
corpus vanish silently. The test also guards the guard — it fails if either
side of the partition is empty, so the comparison can never pass vacuously.

No fixture is named anywhere in the test; the corpus is enumerated at run time.
(Deliberate: another agent is renaming harvested fixtures concurrently.)

Trees are always passed as **directories**, never git refs, so no scratch
worktree is created and the suite cannot leave one behind. (a) and (b) run the
repo's real extension; (c) uses two minimal stub trees, because the question
there is whether a *difference* is reported, and manufacturing one out of the
real extension would pin its current behaviour instead.

## (c) Gaps surfaced

**Gap 1 — `migrationVerdict` reports the FIRST migrating host, and on the
backlog's own verifier event that host is the uninformative one.** Not a stale
premise on the dispatcher's part: the 11:41:05 pair really does carry a
MERGED-STANDALONE. It carries *two* migrating hosts — EXACT at 97 and
EXTENDED/MERGED-STANDALONE at 99 (census output above) — and the function
returns on the first. So the sub-verdict is correctly wired and correctly
silent here. Fixing it is a return-shape decision, larger than "one import plus
a label", so it is surfaced rather than built.

Question for the dispatcher's tier, with the choice stated rather than
deferred: should `migrationVerdict` return **all** migrating hosts (changes the
return shape; `classToRow` consumes only truthiness, but the `--json` payload
and the selftest at `tools/bust-triage.mjs:338` both read `{host, verdict}`),
or keep one host and **prefer the most informative** (scan all, return the
first EXTENDED if any, else the first found — ~5 lines, no shape change)? The
second is the cheaper fix and preserves the current consumer contract; it is
also a judgment about what a triage line is FOR, which is why it is not settled
here. Either way the verifier only becomes checkable after that change.

## (e) Candidate lessons

1. **A backlog verifier can be true about the corpus and still unfireable
   through the tool it names.** The 11:41:05 pair does carry a
   MERGED-STANDALONE; the census sees it and the triage path structurally
   cannot. An entry that names an observation as a verifier is naming it in the
   vocabulary of the tool that FOUND it, and the tool being changed may
   aggregate differently. Worth a line in the backlog's ready-grade definition:
   a verifier is decision-complete only if the named command's *reporting
   granularity* can express the expected result.
2. **"Derive the expected list at test time" needs a second, independent
   derivation path or it is just the implementation restated.** Deriving the
   skip list by re-walking the tool's own three shapes would have inherited its
   parentage exactly; a depth-first search for any `messages` array is shape-
   agnostic and would have survived the historical narrowing. The rule of thumb
   that fell out: the oracle should be able to answer for a fixture shape the
   tool has never seen.
